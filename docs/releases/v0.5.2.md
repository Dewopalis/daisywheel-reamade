# Daisywheel REAmade v0.5.2

v0.5.2 improves recovery when controller mouse input or KDE's pointer session
is interrupted.

## What's changed

- Release held controller mouse buttons when mouse mode ends, a controller
  disconnects, or Daisywheel quits.
- Serialize pointer button notifications so a slow portal cannot accumulate
  an unbounded queue. If a request fails, attempt a final release before
  closing the session.
- Bound pointer movement, button, and scroll requests with timeouts, and
  coalesce queued scroll input.
- Retry unexpected KDE pointer-session failures while LT remains held, with a
  delay between attempts. Explicit permission denial does not trigger repeated
  prompts.
- Add regression coverage for duplicate button presses and interruption
  cleanup.

## Validation

The pull request passed Windows, Debian/AppImage, Fedora RPM, and macOS build
and package checks. The tagged release workflow repeats those checks before
creating its draft release.

## Known limitations

- Sleep/resume and physical controller-disconnect recovery still need hands-on
  testing on KDE hardware.
- macOS remains experimental and has not been tested on a physical Mac.
- Steam Deck Gaming Mode and broader handheld compatibility remain unverified.
